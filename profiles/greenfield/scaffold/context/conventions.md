# Conventions

Fill before the second feature lands; code review enforces it.

- **Naming:** files, components, functions, DB objects, API routes.
- **Layout:** folder structure per repo; where tests live.
- **Errors:** how errors are raised, mapped to responses, and shown to users.
- **Validation:** where (boundary), with what library, server is authoritative.
- **Testing:** unit / integration / e2e split, naming, fixtures, how to run.
- **Logging:** levels, correlation/request IDs, what never gets logged.
- **Comments:** short, what-it-does only (docs/design-principles.md § Comments).
- **Git:** branch / commit / PR naming (AGENTS.md §1).
