# AI Workspace Template

A reusable orchestration workspace for AI-assisted development across a multi-repo
project. It sits **above** your code repos and gives any coding agent the same
operating contract, workflows, verification playbooks, guardrail hooks, and helper
scripts. Distilled from a long production bug-fix / port engagement; all
project-specific context has been removed.

## What's inside

```
AGENTS.md                 canonical rules for every model (Claude imports it via CLAUDE.md)
CLAUDE.md / GEMINI.md     thin shims that import AGENTS.md
workspace.config.json     generated — repos, roles, policies, git naming, modules
workflows/                tool-neutral procedures (build, scaffold-project, analyze, fix, review-pr, log-triage, db-query, export,
                          stakeholder-reply, change-request, port-feature, area-loop,
                          maintain-context, repo-overview)
claude-config/ → .claude/  (installed by setup)
  commands/               slash-command wrappers → workflows (effort pinned; model = session shape)
  agents/                 item-scaffolder, report-formatter, test-runner, fix-verifier, completeness-verifier
  hooks/                  repo_guard.py (enforces read-only/flag-only repos),
                          safe_git_allow.py (auto-allows only safe PR-workflow git)
  skills/setup-workspace/ conversational setup
  model-routing.md        deep/standard/light tier catalog + audit rules
  hooks/post_edit_check.py  syntax-checks every edited file (also `--all` CLI)
docs/                     design-principles, code-slice-scope, verification-guide, git-workflow, lessons-catalog, global-defaults,
                          parity registry, workspace-topology
  templates/              repo-readme.html — shell for each repo's README.html overview page
context/                  project knowledge (per-repo files generated by setup)
mistakes/                 one md per class of agent mistake + INDEX.md (read before work, update on correction)
modules/code-slice/       cs.py: prints only the code a task needs (function at a line, stack trace,
                          call flow, field footprint across screens, changed functions, SQL objects)
modules/                  optional CLIs: tracker (csv/json/gsheet/github/redmine), db-query,
                          usage-metrics (+ --check heartbeat, --coverage), area-index,
                          lint-gate, payload-decode, port-status, log-triage (fingerprint/whitelist/
                          symbolicate), parity, pr-metrics
setup/setup_workspace.py  bootstrap script (--set-type to change project type)
profiles/                 per-type rules, defaults and scaffolds (greenfield, maintenance, port, feature)
repos/                    your project repos are cloned here (gitignored)
```

## Project types

Setup asks which kind of project this is — **greenfield** (fresh code), **maintenance**
(bug-fix), **port** (migration) or **feature** (additions on an existing port), or a
combination — and configures the workspace for it: rules in AGENTS.md §2, scaffolded
context files, default modules, required repo roles and the primary commands. See
`docs/project-types.md`; switch later with `python setup/setup_workspace.py --set-type`.

## Quick start

1. Copy this folder to a new location and `git init` it (it is its own small repo).
   The agent config ships as `claude-config/`; the first run of the setup script
   installs it as `.claude/` (existing files are never overwritten). Commit `.claude/`
   afterwards and you may delete `claude-config/`.
2. Run setup directly (first run — this also installs `.claude/`):

       python setup/setup_workspace.py

   It explains each repo role (frontend, backend, database, reports, docs, tests,
   legacy/reference, infra, other), asks for a git URL or local path per role,
   clones on confirmation, detects stacks, and writes `workspace.config.json`, the
   AGENTS.md workspace map, and `context/repos/<name>.md`. Later changes can be made
   conversationally with `/setup-workspace` inside Claude Code. It finishes with a list of
   roles you did **not** provide and what agents will fall back to.
3. Fill in the `<fill in>` parts of `context/repos/*.md` (structure, ownership,
   known defect patterns). This is the highest-leverage 20 minutes you'll spend.
4. Optional: `python setup/setup_workspace.py --install-global` to install personal
   defaults to `~/.claude/CLAUDE.md` (backs up the existing file).
5. Optional modules: put credentials in `secrets/` (gitignored) —
   `secrets/db-config.json` (see `modules/db-query/`), `secrets/service-account.json`
   for Google Sheets. `pip install` only the drivers you use.
6. Start your agent **from the workspace root** and try `/analyze <item-id>`.

Other commands: `--check` (validate paths/branches/dirty read-only repos),
`--render` (regenerate after editing the config), `--dry-run`.

## Using it with other agents

- Codex, Cursor, Copilot agents and others read `AGENTS.md` natively.
- Gemini CLI reads `GEMINI.md`, which imports `AGENTS.md`.
- Slash commands and hooks are Claude Code features; for other tools, ask the agent
  to "follow `workflows/fix.md` for item 123" — the workflows are self-contained.
- The guardrail hooks are Claude-only; other tools rely on the AGENTS.md rules plus
  your tool's own permission settings (mirror `.claude/settings.json` there).

## Design principles

- **Rules in AGENTS.md, facts in context/, procedures in workflows/.** Only AGENTS.md
  is always loaded; everything else is read on demand (token budget).
- **Enforce what matters with hooks, not memory** — editing a read-only repo or
  force-pushing is blocked mechanically.
- **Adversarial verification before anything leaves the machine** — reviewer round,
  cross-layer verifier, evidence artifact.
- **Cheap tiers for mechanical stages, deep tier for reasoning** — and audit the drift.
- **Lessons become rules** — `docs/lessons-catalog.md` + `/maintain-context`.

## Notes

- Local repo paths are machine-specific; prefer cloning into `repos/` so the config is
  portable across teammates.
- Nothing in your project repos is modified by setup. Per-repo context lives in this
  workspace; if a repo ships its own `AGENTS.md`/`CLAUDE.md`, setup links to it.
